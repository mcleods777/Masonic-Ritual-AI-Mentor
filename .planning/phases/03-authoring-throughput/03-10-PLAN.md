<objective>
Close **CR-03** — the unlocked cross-process read-modify-write on the shared `rituals/_bake-cache/_INDEX.json`. Under `bake-all.ts --parallel N`, multiple `build-mram-from-dialogue.ts` children read-modify-write the same file concurrently; last-writer-wins silently drops D-08 tier/provenance entries, which are never regenerated (index entries write only on fresh renders). Lost fallback-tier lines vanish from `preview-bake.ts`'s scrubber and from the "candidates for premium upgrade" workflow the manifest exists to support.

Fix strategy (code review Option 1 — smallest change consistent with the existing one-ritual-per-child design): each child owns an exclusive per-slug shard (`_INDEX.<slug>.json`), so there is no cross-process contention; readers merge `_INDEX.json` + all shards; the parent consolidates shards into a canonical `_INDEX.json` after a successful wave.

Purpose: Guarantee fallback-tier provenance survives parallel bakes so D-08 keep-and-upgrade stays trustworthy.
Output: Shard-based index writer + shard-merging readers + parent consolidation + a concurrency regression test.
</objective>
